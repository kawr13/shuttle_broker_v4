# Исправления в системе шаттлов

## Исправления для надежного сохранения шаттлов

### 1. Улучшен метод `add_shuttle`
- Перезагрузка конфигурации перед добавлением для синхронизации
- Добавлено логирование для существующих шаттлов
- Улучшена обработка ошибок при сохранении

### 2. Улучшен метод `save_shuttles_config`
- Атомарное сохранение через временный файл
- Подробное логирование списка IP-адресов шаттлов
- Защита от ошибок при сохранении

### 3. Улучшена обработка сообщений от шаттлов
- Перезагрузка конфигурации перед проверкой новых шаттлов
- Более надежное определение новых шаттлов

### 4. Добавлено периодическое сохранение конфигурации
- Автоматическое сохранение каждую минуту
- Запуск в отдельной асинхронной задаче
- Обработка ошибок при периодическом сохранении

## Формат сообщений шаттлов
Поддерживаются следующие форматы:
- `COMMAND_DONE` (например, PALLET_IN_DONE)
- `COMMAND-ID_DONE` (например, FILO-040_DONE)
- `KEY=VALUE` (например, STATUS=NOT_READY)
- `COMMAND STATUS TASK_ID`
- Простые сообщения
