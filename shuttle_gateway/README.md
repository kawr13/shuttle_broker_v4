# Шлюз для управления шаттлами и взаимодействия с WMS

Асинхронный шлюз на Python для взаимодействия между WMS (Warehouse Management System) и шаттлами.

## Возможности

- Опрос WMS для получения документов и задач
- Отправка команд шаттлам и прием их ответов
- Отслеживание состояния шаттлов (батарея, ошибки, сервоприводы, ячейка, склад)
- Управление приоритетами команд
- Автоматическая регистрация новых шаттлов
- Перемещение шаттлов между ячейками и складами

## Установка и запуск

### Требования
- Python 3.8+
- aiohttp
- asyncio (встроен в Python)

### Установка зависимостей
```bash
pip install aiohttp
```

### Запуск
```bash
cd shuttle_gateway
python main.py
```

## Конфигурация

### config.py
Основные параметры системы:
- `WMS_API_URL` - URL API WMS системы
- `USERNAME`, `PASSWORD` - учетные данные для WMS
- `SHUTTLE_COMMAND_PORT` - порт для отправки команд шаттлам (2000)
- `SHUTTLE_RESPONSE_PORT` - порт для приема ответов от шаттлов (8181)
- `POLL_INTERVAL` - интервал опроса WMS (300 сек)
- `STATE_POLL_INTERVAL` - интервал опроса состояния шаттлов (600 сек)

### shuttles.json
Конфигурация шаттлов с их IP-адресами, ячейками и складами.

## Команды шаттлов

Поддерживаемые команды:
- `PALLET_IN` - прием паллеты
- `PALLET_OUT` - выдача паллеты
- `FIFO-nnn`, `FILO-nnn` - операции FIFO/FILO
- `STACK_IN`, `STACK_OUT` - операции со стеком
- `HOME` - возврат в домашнюю позицию
- `COUNT` - подсчет
- `STATUS` - получение статуса
- `BATTERY` - уровень батареи
- `WDH`, `WLH` - размеры
- `MRCD` - данные считывателя
- `MOVE_TO_CELL` - перемещение в ячейку
- `CHANGE_WAREHOUSE` - смена склада

## Приоритеты команд

1. `HOME` (приоритет 1)
2. `PALLET_IN`, `PALLET_OUT`, `MOVE_TO_CELL`, `CHANGE_WAREHOUSE` (приоритет 2)
3. `FIFO`, `FILO`, `STACK_IN`, `STACK_OUT` (приоритет 3)
4. `COUNT` (приоритет 4)
5. `STATUS`, `BATTERY`, `WDH`, `WLH`, `MRCD` (приоритет 5)

## Тестирование

### Проверка WMS
```bash
curl -X GET "http://10.181.80.28:8080/exec?action=IncomeApi.getObjectsShipment" \
     -H "Authorization: Basic MTAwMDoxMDAw"
```

### Проверка шаттлов
Отправка команды:
```bash
echo "PALLET_IN test123\r\n" | nc 10.181.80.135 2000
```

Прием ответа:
```bash
nc -l 0.0.0.0 8181
```

## Логирование

Все операции логируются с уровнем DEBUG в файл `shuttle_gateway.log` и консоль.

Примеры логов:
- `Новый шаттл добавлен: 10.181.80.135`
- `Шаттл 10.181.80.135 перемещён в ячейку Cell_1 на складе Warehouse_A`
- `Состояние шаттла 10.181.80.135: батарея=85%, ошибки=0, сервоприводы=OK`

## Автоматическое добавление шаттлов

При получении сообщения от нового IP-адреса шаттл автоматически добавляется в `shuttles.json` с параметрами по умолчанию:
- `cell`: "Unknown"
- `warehouse`: "Unknown"

Для корректной работы необходимо вручную отредактировать файл и указать правильные ячейку и склад.

## Экспорт состояний

Состояния шаттлов можно экспортировать в JSON файл для анализа и отчетов.
