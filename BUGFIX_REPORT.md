# Отчет об исправлении проблемы с записью неизвестных шаттлов

## Проблема
Неизвестные шаттлы не записывались корректно в файл config.yaml - записывался только один шаттл, а остальные игнорировались.

## Причины проблемы
1. **Race condition**: При одновременном подключении нескольких неизвестных шаттлов они перезаписывали изменения друг друга
2. **Отсутствие блокировки файла**: Не было механизма предотвращения одновременного доступа к файлу конфигурации
3. **Неправильное обновление глобальной конфигурации**: После записи в файл глобальная переменная `config` обнулялась, но не обновлялась корректно
4. **Дублирование обработчиков**: Неизвестные шаттлы могли регистрировать несколько обработчиков сообщений

## Исправления

### 1. Добавлена блокировка в core/config.py
```python
import threading
_config_lock = threading.Lock()

def add_shuttle_to_config(shuttle_id: str, shuttle_ip: str, stock_name: str = 'Главный'):
    with _config_lock:  # Блокировка для предотвращения race condition
        # ... код добавления шаттла
```

### 2. Улучшено обновление глобальной конфигурации
- Теперь глобальная конфигурация обновляется сразу после записи в файл
- Добавляется как сам шаттл, так и его привязка к складу

### 3. **АВТОМАТИЧЕСКОЕ ДОБАВЛЕНИЕ ВСЕХ ШАТТЛОВ** в shuttle_listener.py
- **Все неизвестные шаттлы теперь автоматически добавляются в конфигурацию сразу при подключении**
- Не нужно ждать ответа на STATUS - шаттл добавляется немедленно
- Автоматическое создание обычного обработчика сообщений
- Fallback обработчик только для случаев ошибок

### 4. Улучшена обработка соединений
- Добавлена проверка на уже существующие шаттлы в конфигурации
- Предотвращено дублирование обработчиков сообщений
- Автоматический запрос статуса для новых шаттлов
- Улучшенное логирование процесса добавления

### 5. Добавлены дополнительные проверки
- Проверка существования обработчика перед его регистрацией
- Обработка ошибок при регистрации соединений
- Обработка сырых сообщений с отправкой MRCD
