# 🛠️ Исправление проблемы с URL WMS API

## 🔍 Проблема

Система выдавала ошибку:
```
2025-06-26 16:55:46,999 - shuttle_gateway - ERROR - Ошибка при получении документов из WMS: 0, message='Attempt to decode JSON with unexpected mimetype: text/html;charset=utf-8', url=URL('http://10.181.80.28:8080/?action=IncomeApi.getObjectsShipment')
```

Причина: URL в конфигурации не содержал `/exec`, из-за чего WMS API возвращал HTML вместо JSON.

## ✅ Решение

1. **Исправлен URL в конфигурации**:
   ```yaml
   wms:
     api_url: http://10.181.80.28:8080/exec  # Добавлен /exec
   ```

2. **Улучшена инициализация URL в WmsClient**:
   - Добавлена проверка наличия `/exec` в URL
   - Автоматическое добавление `/exec`, если его нет
   - Исправление двойных слешей и протоколов

3. **Улучшена обработка ошибок**:
   - Проверка типа контента перед парсингом JSON
   - Более подробное логирование ошибок
   - Разделение обработки разных типов исключений

## 📋 Изменённые файлы

1. **config.yaml**:
   - Изменен URL WMS API с `http://10.181.80.28:8080/` на `http://10.181.80.28:8080/exec`

2. **wms_module/wms_client.py**:
   - Улучшена инициализация URL в конструкторе
   - Улучшена обработка ошибок во всех методах
   - Добавлена проверка типа контента

## 🔄 Как работает исправление

1. При инициализации WmsClient проверяется наличие `/exec` в URL
2. Если `/exec` отсутствует, он добавляется автоматически
3. При выполнении запросов проверяется тип контента ответа
4. Если тип контента не JSON, выводится подробная ошибка

## 🚨 Что делать, если проблема повторится

1. Запустите диагностику: `python diagnose_wms_api.py`
2. Проверьте URL в config.yaml
3. Убедитесь, что WMS сервер доступен и работает
4. Проверьте логи на наличие ошибок аутентификации
